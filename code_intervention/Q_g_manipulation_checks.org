* What this is

Q_{-g} is the transition rate matrix after an intervention on gene g: the full transition rate matrix Q with all genotypes that contain g removed. This is the third way of intervening in the paper ("A structural causal framework for interventions on evolutionary accumulation models", https://arxiv.org/abs/2606.12597 , section on CBN and H-ESBCN: "removing, from the fitted transition rate matrix Q, all genotypes with gene g mutated"; also for MHN). The other two are modifying the DAG (or Theta, for MHN) and setting lambda_g = 0 (Theta_gg = 0 for MHN).

The question (2026-09-19): "removing rows and columns" can mean two different things for a transition rate matrix.

1. The off-diagonal entries are copied, and the diagonal is recomputed on the smaller matrix (minus the sum of the rest of the row). This is the intervention we want: transitions into genotypes with g never happen. It is the same as Q with lambda_g = 0, restricted to the genotypes without g.

2. The off-diagonal entries are copied, and the diagonal of the full matrix is kept. The old diagonal is minus the sum of all the rates in the row of the full matrix, including the rates to the genotypes we remove. After the removal those rates are gone from the row, but the old diagonal still counts them, so probability is lost. This is a chain that loses probability ("killed" chain), not the intervention we want.

Answer: the code does 1, by construction, because our transition rate matrices have a zero diagonal. The diagonal is only computed when needed, from the rest of the row. And 2 cannot happen silently: a matrix with a non-zero diagonal makes the code stop, in several places.

I've always thought about 1. 2 seems obviously wrong to me (and for me the diagonal is always a "derived" quantity: the -sum of the rest; I always think of it as secondary, derived, something you compute from the rest, not something you look at because of its intrinsic interest ---yeah, if you want to know things like time to next event, whichever event, you use that diagonal, but only because it puts together the rest of rates--- and always something one checks it really adds to what it should). A reviewer pointed out that what Q_{-g} was wasn't clear. Now I can see where the ambiguity could be, and how it is bad. So this file puts together all the different places where the code for Q_{-g} does stuff, as well as checks that it does what it should.

How to read the locations below: each one gives the file (path from the repository root), the line number(s), and the text of the first line cited. If lines are added or removed, search for that text. Line numbers are as of 2026-09-21.

Note: the Q_{-g} route is only used in the tests, to check the other routes. The results (paper, simulations) use kill_gene (the DAG, or Theta for MHN).

* Where the tests check it

The Q_{-g} route (intervene_cpm_trm_rm_every_gene) is compared, as a full structure (genotype frequencies and hitting probabilities), against the standard kill_gene, against setting lambda_g = 0 (or Theta_gg = 0), against intervening on the fitness landscape, and against models built by hand without the gene. The Q_{-g} route does not go through get_full_output, so it shares no key code with the other routes (see the comments in the test files cited below).
